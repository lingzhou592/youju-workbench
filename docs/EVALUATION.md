## 二、对照协议

### 共同条件

- 同一 Brief；
- 同一品牌约束；
- 同一批事实卡；
- 同一模型、同一温度、同一超时；
- 同一天、同一网络环境（尽量）。

### A 侧：直接提示基线

- 输入：品牌约束 + Brief + 事实卡原文；
- 指令：按“标题 / 正文 / 话题 / 配图建议”四段输出；
- 不要求引用，不提供规则反馈；
- 基线也拿到完整资料，**不故意写弱**。

### B 侧：工作台流程

- 结构化生成：共享正文 + 两个标题候选；
- 规则检查自动运行；
- 引用编号 + 原文摘录；
- 评测时取候选 A 的标题 + 共享正文。

### 运行方式

- UI：历史与评测 → 对照评测 → 选择用例 → 运行这条对照；
- 批量：历史与评测 → 对照评测 → 批量运行 10 条（约 20 次模型调用，可中止）；
- 脚本：`node scripts/e2e-comparison.mjs`（需本地 Mock 或真实模型）。

## 三、指标定义

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| 结构完整 | 标题、正文、标签、配图建议是否都解析到 | 直接提示按四段解析 |
| 规则通过 | 通过项 / 总检查项 | 使用同一套规则引擎 |
| 引用有效率 | 可解析引用中能定位的比例 | 直出通常为 N/A |
| 无依据数字 | 数字无法在引用资料中找到的数量 | 字符串级，不是语义判断 |
| 人工事实支持 | 1–5 分 | 评分者判断事实是否被资料支持 |
| 人工品牌适配 | 1–5 分 | 评分者判断语气/人群/品牌约束 |
| 耗时 | 本次调用实际耗时 | 包含网络与模型时间 |
| 模型 | 模型名、来源（实时/Mock） | Mock 不可作为质量证据 |

**不合成总分。** 结构、规则、引用、人工评分分别展示；避免用一个加权分数掩盖不同维度。

### 人工评分 rubric

**事实支持**

1. 多处无依据/与资料冲突；
2. 有明显无依据表述；
3. 大体有依据，但有 1–2 处需要核对；
4. 事实基本可回查，个别表达需要人工确认；
5. 事实性表述均可回查，未发现编造。

**品牌适配**

1. 明显不符合品牌语气/人群；
2. 多处不符合；
3. 基本可用，但语气或人群有偏差；
4. 符合品牌语气与人群，少量表达可优化；
5. 语气、人群、必提信息与约束都匹配。

## 四、工程验证结果（非模型质量结论）

### 单元测试

```bash
npm test
```

当前结果：**9 个测试文件，44 个测试全部通过**。

覆盖：

- 规则边界与句末引用归属；
- 段落级引用上下文；
- 检索排序与归档降权；
- 版本/审核/确认失效；
- reducer 快照行为；
- 导出草稿/定稿；
- LLM 缺 key、JSON 提取、schema 校验；
- 评测指标；
- 事实卡导入。

### Mock E2E

```bash
npm run mock
# .env.local 指向 http://127.0.0.1:8787/v1
node scripts/e2e-mock.mjs
node scripts/e2e-comparison.mjs
```

已验证：

- Brief → 依据 → 生成 → 选候选 → 模型审核 → 定向修订 → 人工确认 → 导出；
- 对照评测单条运行 + 人工评分保存；
- 无控制台错误。

## 六、已知局限

1. 关键词检索可能漏掉语义相关但字面不重合的资料；
2. 规则只能做字符串级检查，无法判断事实是否真实；
3. 模型审核可能漏判/误判，置信度未校准；
4. 人工评分受评分者经验影响；
5. 10 组对照样本量小，不能外推到所有文旅品牌；
6. 当前未做多评分者一致性、重复运行和置信区间；
7. 当前未接入真实投放效果，不能声称转化提升。

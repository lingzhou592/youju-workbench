# 有据 · 文旅营销素材生成与校验工作台

> 产品终案。只保留最终选题、范围、流程与实现口径，不包含方案比较。

## 一、一句话定位

面向文旅品牌营销策划与文案人员，把品牌约束、活动 Brief 和事实资料，转成**有事实依据、可审核、可修订、可导出**的小红书图文文案。

**V1 只服务一个场景**：文旅品牌的小红书图文文案生产，输出标题、正文、话题标签和配图建议（文字）。

---

## 二、背景与问题

文旅营销内容有三个同时存在的要求：

1. **快**：周末活动、节点促销需要短周期产出；
2. **准**：价格、时间、人数、报名方式、服务承诺不能编；
3. **稳**：品牌语气、必提信息和禁用表达要一致。

通用模型能解决“快”，但会带来新的问题：

- 编造不存在的价格、赠品、效果承诺；
- 品牌要求靠人记，换一次生成就漂移；
- 审核意见散落在聊天里，改完之后不知道哪些结论还有效；
- 没有可复用的评测方法，无法说明流程是否真的改善了输出。

本产品的核心不是“让模型写得更好看”，而是**把内容生产变成一条有证据链的质量流程**：资料可回查、检查可复现、修改可追溯、判断有人负责。

---

## 三、用户与任务

### 主要用户

- 文旅品牌/景区的新媒体运营；
- 营销策划/内容策划；
- 内容审核/品牌审核人员。

### 典型任务

> 周末活动上新，需要给大学生/亲子家庭/上班族写一篇小红书笔记；品牌有必提信息、禁用表达和语气要求；发布前需要核对价格、时间、人数和报名方式。

### 用户真正需要的

- 不是“更多版本文案”，而是**能判断哪一版可以用**；
- 不是“模型说没问题”，而是**问题在哪里、依据是什么、谁确认过**；
- 不是“生成完就结束”，而是**修改后旧结论自动失效**。

---

## 四、产品范围

### V1 做

- 单平台：小红书图文；
- 单品牌：一个当前品牌配置；
- 单场景：活动/线路推广；
- 文案结构：标题、正文、话题标签、配图建议；
- 事实卡：可编辑、可导入、可归档、可检索；
- 三层校验：程序规则、模型建议、人工确认；
- 定向修订、版本链、句级 diff；
- Markdown / JSON 导出；
- 20 条测试用例、10 组对照评测、离线规则演示；
- 本地运行、浏览器本地存储、OpenAI-compatible 模型接口。

### V1 不做

- 图片/视频生成；
- 多平台适配与自动发布；
- 真实投放实验、点击率预测；
- 账号体系、数据库、团队协作、权限；
- 向量检索/嵌入服务（首版用可解释的关键词检索）；
- 平台审核认证或“合规保证”。

## 五、核心流程

### Step 1 · Brief

字段：

- 活动名称（必填）
- 推广对象（必填）
- 活动目标（必填）
- 目标人群（必填）
- 核心卖点（必填，一行一个）
- 语气补充（可选）
- 内容限制（可选）
- 渠道：固定“小红书”

交互：

- 三个示例 Brief 一键载入，并同时选好推荐事实卡；
- 必填校验，字段级错误；
- 自动保存草稿；
- 生成后 Brief 冻结为运行快照，后续修改只用于下一次生成。

### Step 2 · 依据

- 根据 Brief 提取中文二元组、英文词和关键词；
- 按标题/标签/正文/分类加权，使用逆文档频率降低“价格”“报名”等泛词权重；
- 加入分类相关性：时间排期、价格政策、服务承诺、人群洞察等与 Brief 场景匹配时加分；
- 归档资料显著降权；
- 展示命中词、相关度、分类、来源、状态；
- 人工勾选/取消，允许全选推荐组合、只看已选、显示已归档；
- 选择归档资料时提示“请确认是否仍然适用”。

**明确说明**：这是关键词匹配，不是向量检索，也不是自动判断真伪。

### Step 3 · 生成

一次模型调用返回：

- 共享正文；
- 两个标题候选：
  - A：从具体场景/画面切入；
- B：从目标人群的需求/阻力切入；
- 每个标题附角度说明、推荐理由、待验证假设；
- 共享标签、配图建议；
- 引用映射：事实卡编号 + 原文摘录 + 用途；
- 模型自查说明。

产品口径：

- 两版只叫“标题候选 A/B”，**不是线上 A/B 测试**；
- 不展示点击率预测；
- 正文、标签、配图建议保持一致，避免多变量混淆；
- 选定标题后进入版本链；切换候选会创建新版本，旧审核不继承。

### Step 4 · 校验与修订

#### 4.1 程序规则（自动）

| 检查 | 通过 | 提醒 | 未通过 |
| --- | --- | --- | --- |
| 标题长度 | 6–20 字 | 21–24 字或 4–5 字 | <4 或 >24 字 |
| 正文长度 | 250–700 字 | 150–249 或 701–1000 | <150 或 >1000 |
| 话题标签 | 3–6 个，均以 # 开头，无重复 | 数量越界/缺 #/重复 | 0 个或 >8 个 |
| 必提信息 | 每条关键词按 all/any 覆盖 | — | 缺少关键词 |
| 禁用表达 | 未出现 | — | 出现，附上下文 |
| 绝对化表达 | 未出现内置词表 | — | 出现 |
| 引用存在 | 所有引用编号在快照中 | 无引用 | 出现未知编号 |
| 引用数量 | 正文 ≥2 个 | 1 个 | 0 个 |
| 引用原文 | 摘录可在事实卡中定位 | 无法定位/缺摘录 | — |
| 数字依据 | 数字可在所在句/段落的引用资料中找到 | 含数字但无引用 | 数字无依据 |
| 标题候选差异 | 两个标题不同且角度不同 | 角度标签相同 | 标题相同 |
| 标点规范 | 无连续感叹号，感叹号 ≤2 | 连续/过多 | — |
| 配图建议 | 2–4 条，具体画面 | 数量不符/空泛词 | — |
| 归档资料 | 未使用归档资料 | 使用了归档资料，提示确认 | — |

补充：

- “必提信息”在配置里是 `{ text, keywords[], match }`，检查关键词覆盖，不要求逐字复制；
- 数字检查是字符串级定位，不是语义蕴含；
- 模型常把 `[F-xxx]` 写在句末标点后，规则会先把紧跟标点的引用归到前一句/段落；
- 规则结果确定、可复现，不判断事实在现实中是否成立。

#### 4.2 模型审核（手动触发）

输出问题数组：

- 类别：事实依据 / 品牌语气 / 人群匹配 / 结构表达 / 合规风险 / 其他；
- 严重程度：error / warning / info；
- 原文片段、问题描述、依据事实编号、修改建议、模型自评置信度。

交互：

- 问题可勾选进入修订；
- 可标记已处理、忽略并填写原因；
- 引用的原文无法在文案中定位时，服务端会清空片段并标为低置信度；
- 置信度明确标注“模型自评（未校准）”；
- 模型审核失败不阻塞规则检查；失败记录会保留。

#### 4.3 定向修订

- 选中问题 + 修订指令；
- 服务端只做定向修改，不新增事实；
- 保留仍然有效的引用；
- 返回修订后标题/正文/标签/配图建议、引用、变更说明、未解决问题；
- 新版本展示句级 diff；
- 修订历史可回看、可恢复为新版本。

#### 4.4 人工确认

清单：

- 事实准确；
- 语气符合品牌；
- 信息完整；
- 适合实际发布；
- 若模型审核未完成，需勾选“已知晓”。

备注至少 10 字，记录判断依据。

规则仍有未通过项时：

- 可以确认，但必须填写至少 10 字的 override 理由；
- 导出物保留“规则未通过仍确认”的原因。

确认绑定 `versionId + contentHash`；任何编辑、修订、切换候选或恢复都会创建新版本，旧确认不继承。

### Step 5 · 导出

- **发布文案**：自动去掉 `[F-xxx]`，适合直接复制到平台；
- **Markdown 记录**：完整正文 + 引用脚注 + 事实依据表 + 规则检查 + 模型建议 + 人工确认 + 修订记录 + 输入快照；
- **JSON 数据**：完整 Run、当前版本、当前审核、当前确认；
- **草稿/定稿**：未确认导出会标注“草稿（未经人工确认）”；
- **内置示例**：导出物保留“非模型实时生成”标记。

## 六、信息架构

### 1. 工作台 `/`

五步流程 + 右侧校验栏。

- 顶部：页面标题、模型状态、使用说明、历史入口；
- 步骤条：Brief → 依据 → 生成 → 校验与修订 → 导出；
- 主区：当前步骤内容；
- 右栏：任务摘要 / 规则检查 / 模型建议 / 人工确认。

### 2. 品牌与资料 `/sources`

- 品牌约束编辑 + 提示词预览；
- 事实资料库：搜索、分类/状态筛选、排序、新增/编辑/归档/删除、导入/导出；
- 检索预览：观察关键词排序；
- 数据管理：全量导出/导入、恢复演示资料。

### 3. 历史与评测 `/history`

- 运行记录：打开、删除、清空；
- 测试用例：20 条，可载入工作台；
- 对照评测：单条/批量运行、两侧输出、自动指标、人工评分、记录导出；
- 规则演示：三个离线样例，不调用模型。

## 七、数据模型

采用**单个 Run 聚合 + 线性版本链**。

```ts
type Run = {
  id: string
  title: string
  createdAt: string
  updatedAt: string
  input: {
    brief: Brief
    brand: BrandConfig
    facts: FactCard[]       // 运行快照
  }
  generation: {
    titles: [TitleCandidate, TitleCandidate]
    body: string
    tags: string[]
    imageSuggestion: string[]
    citations: Citation[]
    selfCheck: string[]
    source: "live" | "mock" | "sample"
    modelMeta?: ModelMeta
  }
  versions: DocumentVersion[]
  activeVersionId: string
  reviews: ReviewRecord[]
  confirmations: ConfirmationRecord[]
  sample?: boolean
}

type DocumentVersion = {
  id: string
  parentVersionId: string | null
  candidate: "A" | "B"
  title: string
  body: string
  tags: string[]
  imageSuggestion: string[]
  citations: Citation[]
  contentHash: string
  source: "generation" | "candidate-switch" | "manual-edit" | "revision" | "restore"
  revisionNotes?: string[]
  createdAt: string
}
```

关键规则：

- 当前审核 = 同一 `versionId + contentHash` 的最新 review；
- 当前确认 = 同一 `versionId + contentHash` 的最新 confirmation；
- 编辑/修订/切换/恢复都追加新版本；
- 旧审核与确认保留为审计历史，但不对新版本生效；
- 恢复旧版本 = 以旧内容创建新版本，来源标记 `restore`；
- 项目切换候选时，优先复用该候选最近一次版本，避免丢失编辑。

持久化：

- 单 key `youju.state.v1`；
- 首次访问写入 seed；
- 客户端挂载后读取，避免 SSR 水合问题；
- 损坏 JSON 时加载初始示例并提示；
- 配额不足时提示导出/清理；
- 全量 JSON 导入/导出。

## 八、检索

### 实现

- 中文二元组 + 英文词；
- 标题 / 标签 / 正文 / 分类加权；
- 逆文档频率（IDF）降低泛词权重；
- 分类相关性（时间排期、价格政策、服务承诺、人群洞察等）；
- 归档资料乘 0.35；
- 返回命中词、相关度、原因。

### 边界

- 不是向量检索；
- 不做语义改写匹配；
- 不做自动事实核查；
- 最终由人工勾选资料。

## 九、模型交互

### 环境变量

```bash
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-chat
LLM_TIMEOUT_MS=60000
```

### 客户端

- 原生 `fetch` 调 OpenAI-compatible Chat Completions；
- 服务端惰性读取 env，缺 key 不影响构建；
- 超时、401/403、429、5xx、网络错误、非 JSON、schema 错误分别映射；
- 响应统一信封 `{ ok, data, meta }` / `{ ok, error }`；
- 不记录密钥；错误信息不含 Authorization。

### 输出约束

- 生成：严格 JSON；两个标题；共享正文；引用编号 + 原文摘录；标签 3–6；配图建议 2–4；事实性表述后标 `[F-xxx]`。
- 审核：只输出问题 JSON；quote 必须逐字来自文案；最多 8 条；无问题返回空数组。
- 修订：只做定向修改；不新增事实；保留引用；返回变更说明与未解决问题。
- 直出基线：四段纯文本（标题/正文/话题/配图建议），不要求引用。

### 失败处理

- 保留输入；
- 显示错误码、可操作建议、重试；
- 模型审核失败仍展示规则检查；
- 不以样例冒充实时生成。

## 十二、视觉与交互

- 暖白纸感背景、深墨绿侧栏、墨绿主操作；
- 中文系统字体，不依赖外部字体服务；
- 桌面左导航 + 主内容 + 右侧校验栏；窄屏单列；
- 细边框、少量阴影、克制留白；
- 引用显示为可点击小标记，悬停/聚焦显示事实卡原文；
- 规则、模型、人工三层视觉区分；
- 加载、空状态、错误、确认、toast 均有明确反馈；
- 键盘可操作，模态框焦点锁定与 Esc 关闭。

## 十三、成功标准

- 从 Brief 到可发布文案可在 5 分钟内走通；
- 每个事实性数字都能回查；
- 修改后旧审核/确认明确失效；
- 导出物可直接交给审核人复核；
- 无 key 时也能预览完整流程，不伪造实时生成；
- 测试、构建和错误处理可复现。

## 十四、风险与后续

### 风险

- 关键词检索召回有限，可能漏掉相关事实；
- 规则只做字符串检查，不能替代事实核查；
- 模型可能漏判/误判，置信度未校准；
- 本地存储不适合团队协作；
- 公开部署前缺少鉴权、限流、审计。

### 后续

1. 混合检索与引用可追溯；
2. 多平台适配；
3. 团队协作与审核流；
4. 多评分者、重复运行的评测；
5. 图片/素材生成与来源管理；
6. 在明确授权下接入发布与回流数据。

---

## 十五、口径备忘

- 两版标题是**候选素材**，不是 A/B 测试；
- 引用可定位 = 能在事实卡快照中回查，不是事实已核实；
- 模型建议 = 待人工判断的线索，不是平台审核；
- 关键词检索 = 中文二元组 + IDF + 分类相关性，不是向量检索；
- 内置示例 = 人工编写的流程预览，不是模型实时生成；
- Mock = 工程联调，不是模型质量证据；
- 测评 = 单模型/单评分者/单次运行，不声称统计显著。
